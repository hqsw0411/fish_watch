# 当前项目服务器部署指南

> 更新：2026-10-19。适用于当前 React + FastAPI + SQLite 区域原型。
> 本文提供已准备的部署包和 Linux 命令；尚未连接 ACS，尚未在服务器执行。

## 1. 实际部署的内容

当前项目可以由一个 FastAPI/Uvicorn 服务同时提供网页、地图静态文件和 API。前端已经编译进 frontend/dist，服务器运行时只需要 Python 3.12 或更高版本和 Web 服务依赖。

```text
浏览器 → ACS 端口映射/反向代理/SSH 隧道 → Uvicorn :8000
                                          ├── /             前端网页
                                          ├── /assets/*     JS/CSS
                                          ├── /land.geojson 离线底图
                                          └── /api/*        FastAPI 接口
                                                └── sample.sqlite3
```

这里有两个数据库，职责必须区分：

| 文件 | 当前用途 | 是否被现有网页/API读取 |
|---|---|---|
| data/samples/patagonia_6blocks_2012_h1/sample.sqlite3 | 网格月浏览缓存，启动时由 sample.csv 自动创建 | 是 |
| data/database/fisheries_forecast.sqlite3 | 15 张表的研究数据库，含原始努力量、环境、特征和来源 | 否，当前只随包部署，接入路由是后续工作 |

现有真实路由是 /api/health、/api/catalog、/api/dictionary、/api/sample 和 /api/temperature。此前方案中的 /api/v1/* 是规划接口，当前没有实现。不要用规划路径做部署验收。

部署包包括后端、前端源码与构建产物、配置、14,400 行区域样例、研究数据库、2012 年 GFW 月度 ZIP、区域 NetCDF 及追溯信息。浏览缓存不打包，服务器首次启动自动生成。

Windows 的 .venv、node_modules、.python-deps、.week1-deps、私钥和 .env 不打包；服务器依赖必须在 Linux 环境安装。

## 2. 第一步：上传部署包

本机已准备：

```text
output/deploy/fisheries-server.tar.gz
output/deploy/fisheries-server.tar.gz.sha256
```

通过 ACS 提供的文件上传功能，把这两个文件上传到服务器个人目录。如果平台“我的数据”使用独立目录，先查看上传后显示的真实文件路径，再切换到该目录。没有上传文件时，WebShell 无法读取 Windows 的 D: 盘。

如平台允许 SSH/SCP，也可以从本机 PowerShell 上传：

```powershell
# SSH_HOST、PORT、USER 必须使用平台提供的实际值。
scp -P PORT "D:\海洋渔业预测\output\deploy\fisheries-server.tar.gz" USER@SSH_HOST:~/
scp -P PORT "D:\海洋渔业预测\output\deploy\fisheries-server.tar.gz.sha256" USER@SSH_HOST:~/
```

这两个示例中的地址和用户名都是占位符，不能直接执行。ACS 门户地址、WebShell 登录节点和应用运行节点可能是不同机器。

## 3. 第二步：解压到一个新目录

在服务器 WebShell 中执行。以下命令假定文件上传到了家目录：

```bash
cd ~
ls -lh fisheries-server.tar.gz fisheries-server.tar.gz.sha256
sha256sum -c fisheries-server.tar.gz.sha256
# 首次部署使用。若 fisheries-server 已存在，换一个空目录解压，保留旧版本。
mkdir fisheries-release-20261019
tar -xzf fisheries-server.tar.gz -C fisheries-release-20261019
cd ~/fisheries-release-20261019/fisheries-server
pwd
ls deploy/linux/start.sh frontend/dist/index.html
```

SHA-256 检查必须显示 OK。这个目录是后续命令所说的“项目根目录”。

如果上传目录不同，只替换上传文件路径；不要在没有项目的 ~ 目录直接执行 scripts/start 之类的相对路径。

## 4. 第三步：建立 Python 运行环境

先检查：

```bash
python3 --version
```

如果已经是 Python 3.12+：

```bash
python3 -m venv .venv
```

截图显示当前启用了 Conda base。如果 python3 版本不足，可用 Conda 新建独立环境，再创建项目虚拟环境：

```bash
conda create -n fisheries-web python=3.12 -y
conda activate fisheries-web
python -m venv .venv
```

两条路径择一。之后统一使用项目自己的解释器：

```bash
.venv/bin/python -m pip install -r deploy/linux/requirements-runtime.txt
.venv/bin/python scripts/check_deployment.py
```

Web 运行依赖只安装 FastAPI、Uvicorn 及其依赖，不需要安装 pandas、xarray 或 Copernicus Toolbox。

若服务器无法访问 Python 包索引，应在联网的兼容 Linux 环境准备 wheels，通过 pip --no-index --find-links 安装；不要复制 Windows 环境。若安装失败，保留完整错误，以区分网络、镜像版本和系统兼容问题。

研究数据库重建和重新获取数据另需 backend/requirements.txt；不必为了打开网页先运行 build_database.py。

## 5. 第四步：首次启动

先用前台方式启动，方便看到错误：

```bash
bash deploy/linux/start.sh
```

默认监听 127.0.0.1:8000，只能从运行节点自身或隧道访问。脚本会检查部署文件，然后用单 worker 启动 Uvicorn，避免多个 worker 同时初始化 sample.sqlite3。

另开一个 WebShell，进入同一项目目录验收：

```bash
cd ~/fisheries-release-20261019/fisheries-server
.venv/bin/python scripts/check_deployment.py --url http://127.0.0.1:8000
```

验收会实际访问健康接口、单网格窗口、整月 2,400 格、温差图层、网页 JS/CSS 和离线底图，并核对捕捞时长合计。

成功后，2012-01 整月 fishing_hours 应为 8572.1918。所有查询都使用本地样例，无需联网下载 GFW/CMEMS。

## 6. 第五步：让自己的电脑打开网页

服务器本机验收成功不代表电脑浏览器已经能访问；还需要一种有效的网络通道。

### 方式 A：ACS 应用端口映射

如果 ACS 支持 Web 应用或应用端口映射，按平台指引申请运行节点，将应用内部端口配置为 8000，启动命令使用：

```bash
FISHERIES_HOST=0.0.0.0 bash deploy/linux/start.sh
```

在浏览器打开 ACS 返回的应用 URL。具体菜单和地址必须以平台实际配置为准；当前截图未提供这些信息。

当前前端使用根路径 /api、/assets、/land.geojson。代理需要把这些路径交给同一个应用。如果平台仅提供 /proxy/8000/ 形式的子路径，不能只修改一个页面 URL；需要调整前端 base/API 基址及代理路由后重打包。

### 方式 B：SSH 隧道

如果能够 SSH 到运行应用的节点，服务保持默认 127.0.0.1 启动，在本机另开 PowerShell：

```powershell
ssh -p PORT -N -L 18000:127.0.0.1:8000 USER@APP_HOST
```

然后打开：

```text
http://127.0.0.1:18000
```

APP_HOST 必须是应用所在节点。若只能 SSH 到登录节点，需要平台给出跳板配置或计算节点访问方法。

### 方式 C：专用服务器内网直连

若这是允许长期运行服务的独立机器，且电脑可访问应用节点 IP，可监听 0.0.0.0 并在浏览器打开 http://应用节点IP:8000/。端口访问规则由服务器管理员配置。

10.32.34.110:6080 是目前已知的 ACS 门户入口；没有证据表明它也是应用所在节点。不要直接猜测项目地址为 10.32.34.110:8000。

## 7. 长期运行

ACS 页面带有作业管理，当前终端提示符是 user@login-node。这可能是登录节点，不能据此认定它允许长期运行 Web 服务。

- ACS/集群：优先使用平台 Web 应用、交互作业或服务作业；申请到运行节点后再启动。登录节点适合上传、解压和环境准备。
- 专用 Linux 机器：管理员可使用 systemd 或其他进程管理服务持续运行。
- 专用机器临时演示：可以在项目根目录使用以下 nohup 命令，默认仍只监听本机：

```bash
mkdir -p logs
nohup bash deploy/linux/start.sh > logs/web.log 2>&1 &
echo $! > logs/web.pid
tail -n 60 logs/web.log
```

nohup 只能处理终端关闭，不会绕过集群作业时限、节点回收或平台进程清理。

前台服务按 Ctrl+C 停止。查看临时后台进程先用 ps -fp "$(cat logs/web.pid)" 核实，确认是本项目后再停止。

## 8. 常见问题

| 现象 | 检查办法 |
|---|---|
| scripts/... No such file | 尚未上传、解压，或没有切换到项目根目录；先 pwd 和 ls |
| 服务器访问 /api/health 成功，电脑打不开 | 检查 ACS 映射、SSH 隧道、应用节点与网络端口 |
| 网页 404，API 正常 | 确认 frontend/dist/index.html 在部署包中，启动后未移动目录 |
| 网页空白，JS/CSS/API 404 | 检查是否被平台放到子路径；当前构建使用根路径 |
| Python 语法错误 | 检查实际启动解释器是 Python 3.12+ |
| 缺少 FastAPI/Uvicorn | 确认 pip 和启动都使用 .venv/bin/python |
| permission denied / readonly database | 样例目录需要可写，首次启动要建立浏览缓存 |
| address already in use | 检查现有服务或使用 FISHERIES_PORT=8001；同步修改映射和验收地址 |
| 找不到 2012 年以外数据 | 当前部署包只有区域半年样例，扩充数据是下一阶段 |
| 研究库更新了但网页没变 | 当前路由读取 sample.sqlite3；尚未接入 15 张表的研究库 |

## 9. 维护和重新打包

本地修改前端后，应重新构建并重新打包：

```powershell
cd D:\海洋渔业预测\frontend
npm.cmd run build
cd ..
# python 必须指向有 Python 3.12+ 的环境，也可用本机已配置的完整路径。
python scripts/package_server.py
```

打包脚本仅收集明确列出的文件，并生成 deployment-manifest.json 和压缩包 SHA-256 文件。后续更新请发布到新的 release 目录，独立验证后再切换平台启动目录。

大数据全量部署另见 docs/完整数据服务器部署方案.md。先把当前网页/API在服务器跑通，再扩充 GFW 年份和环境覆盖，最后决定 PostgreSQL/PostGIS 的迁移与路由接入。
