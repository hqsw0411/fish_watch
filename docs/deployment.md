# 部署前核验与回滚

此文描述待执行步骤。当前清理副本尚未部署，原服务和数据保持原状。

1. 核实当前服务的代码根、Python 环境、作业和入口代理，记录进程/作业标识、端口、健康检查和发布指针。已有同步监督器会轮询 `latest.json`；在批准前不更改指针。
2. 为代码、部署配置和未提交修改保留可恢复快照。数据库用对应引擎的一致性备份或经过验证的存储快照；不能把活动数据库的普通文件复制视为一致性备份。
3. 在新的版本目录安装运行依赖，另行完成前端构建。数据通过 `FISHERIES_SAMPLE_DIR` 指向只读的已验证发布；权重通过 `FISHERIES_MODEL_DIR` 配置。
4. 先检查源文件与数据清单、CSV 哈希、SQLite 完整性、逐月覆盖和环境变量；确认研究数据库与浏览索引的用途，避免误替换。
5. 在隔离环境验证 `/api/health`、`/api/catalog`、区域查询、温差查询、静态资源；模型文件和环境一致后再验证预测。保留原版本相同请求的结果进行比较。
6. 形成具体文件差异、快照位置、恢复验证结果、切换/回滚命令。取得用户明确批准服务器写回后，才按新版本目录逐步切换。
7. 切换后检查服务与数据哈希；失败时恢复旧代码版本和旧发布指针。不要删除旧发布或原始数据。

## 外部数据策略

`data-manifests/` 只保存目录审计取得的路径和大小等轻量信息。未计算的哈希及尚未确定的存储 URI 保持空值。实际数据留在受控服务器或外部存储，不提交 Git。

可在独立副本中配置 DVC，但不能在运行数据目录执行会移动数据的操作。凭据留在外部凭据配置，不写入清单、Git 历史或公开 URL。

## 运行监督器

`python deploy/supervise.py --check --releases <目录> --app <代码根>` 只做发布检查。省略 `--check` 会启动/切换 API 子进程，因此只有在批准的隔离或部署流程中执行。该监督器不会因为克隆仓库自动运行。

历史的服务器专用启动脚本保存在本地输入快照中。清理仓库不注册 cron、不调用 sbatch/scancel、不修改已有作业。
